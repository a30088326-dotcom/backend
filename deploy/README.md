# AWS deployment

Frontend: Amplify Hosting connects to the frontend GitHub repository. Backend: a private ECR image on ECS Express Mode provides an HTTPS API. Data uses the 120 separate `DYNAMODB_TABLE_PREFIX-entity` tables, and employee uploads use a private S3 bucket.

This folder prepares deployment; it does not deploy resources or prove migration completion. The CloudFormation template defaults `DeploymentReady=NO`. Do not enable the API until the native DynamoDB migration, imported data, files and complete employee/admin workflows pass.

## Prepare and deploy

1. Run `node deploy/generate-template.cjs`. Review `aws-backend.template.json`, target AWS account and region, and the selected public subnets. The stack needs named application roles and an ECS infrastructure role. The application task role is restricted to this app's table prefix and its own S3 upload prefix. It cannot create or drop tables, administer IAM, read arbitrary secrets, or access other buckets.
2. Create the stack with `DeploymentReady=NO`. This creates a private versioned upload bucket, immutable ECR repository, Secrets Manager secret, log group, ECS cluster and roles. It does not start billable API compute or an ALB yet. The secret and storage still have ordinary AWS storage charges.
3. Configure SMTP_USER and SMTP_PASS privately in the generated JSON secret. JWT_SECRET is generated by AWS. Never put any secret in Git, Amplify VITE variables, image build arguments, reports or logs. This template does not copy local `.env` files.
4. Complete and verify the 120-table import. Import all registered employee uploaded files into the bucket under `uploads/<existing filename>` without changing their private `/api/files/<filename>` references. Check file count, byte lengths and checksums against the backup, and compare all table keys and record counts. Preserve existing target data unless an explicit migration reconciliation has identified it as obsolete.
5. Run native DynamoDB integration tests, not MySQL tests alone. Ensure the AWS runtime never connects to MySQL, and that authorization, transactions/concurrent updates, employee login, all module CRUD, leave balances and approvals, attendance, invitations and private uploaded-file access work against DynamoDB.
6. From the backend repository root, build the container with `docker build -f deploy/Dockerfile -t peoples-hr-api:COMMIT .`. Scan it, push it to this stack's ECR repository, and obtain its SHA-256 image digest. The Docker context excludes local `.env`, SQL backups, uploads, reports and Git metadata.
7. Update the stack with the digest-pinned `ApiImage`, exact `FrontendOrigin` and `DeploymentReady=VERIFIED`. API startup refuses a MySQL URL or disk upload storage. Before opening the listener it checks that all 120 DynamoDB table key schemas are ACTIVE and that S3 is reachable. These startup checks do not replace data migration verification.
8. Set Amplify `VITE_API_URL` to the returned HTTPS API origin, with no trailing slash and no `/api` suffix. `amplify.yml` refuses a missing or localhost API origin. Apply `frontend/deploy/amplify-rewrites.json` to Amplify redirect/rewrite rules so deep links such as `/onboarding` and `/performance` load directly. Rebuild Amplify after changing VITE variables.
9. Test the hosted system in the browser and after refresh. Confirm CORS allows only the selected Amplify origin, anonymous private files fail, employees cannot read other employees' files, writes persist in DynamoDB, and invitations point to the new site. Verify uploaded files remain available after replacing the API task.
10. After hosted acceptance and a verified restorable SQL/files backup, remove only the explicitly identified obsolete AWS deployments and the requested local application MySQL database. Do not remove MySQL system databases, unrelated cloud applications or the source before successful cutover.

## Capacity and recurring cost

API defaults are 0.25 vCPU, 512 MiB RAM, minimum 1 and maximum 2 Fargate tasks. ECS Express Mode adds an HTTPS Application Load Balancer and supporting resources. Fargate, ALB, logs, data transfer, S3, ECR, Secrets Manager and DynamoDB are charged separately; this is not a free-only deployment. No NAT gateway is provisioned by this template. A maximum of 2 tasks bounds ordinary steady-state scaling; deployments can temporarily use replacement capacity. Review AWS estimates before turning the API service on. Increase capacity only after measuring usage.

App Runner was considered but is closed to new customers after April 30, 2026. ECS Express Mode is its documented replacement. Standard Lambda synchronous requests are capped at 6 MB, while this app accepts 10 MB documents, so the existing upload flow requires a container or a separately implemented direct-to-S3 upload flow.
